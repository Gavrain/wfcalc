# 元素计算的具体例子

> 全部数字由 `node packages/demo/src/gen-element-examples.mjs` 用**真实数据**跑出，
> 不是手写示例——改代码后重跑这个脚本即可核对。
>
> 统一用一个武器：**赤毒·卡拉克（Kuva Karak）**，基础面板
> `冲击 7.13 / 穿刺 6.21 / 切割 9.66 = 23.00`；除注明外带 **+165% 基伤（膛线）** 与 **玄骸火焰 50%**。

---

## 计算顺序（一句话版）

```
面板伤害
  → ① 玄骸加成（面板总伤 × 比例，并入面板）        D-017：在基伤之前
  → ② 基伤 ×(1 + Σ基伤Mod% + 镀层%)
  → ③ 物理 %Mod：各自只放大自己那一型
  → ④ 元素 %Mod：加量 = (①+② 的新面板总伤) × 元素%
  → ⑤ 同类型先合并 → 两两配对 → 复合元素           D-006 / D-023
  → ⑥ 汇总
```

**两个最容易算错的点**：

1. **元素 % 的基数是「玄骸 + 基伤之后、物理 % 之前」的整份面板总伤**，不是单个元素的值。
   例：② 之后总伤 91.425，+90% 火 → 火 Mod 加量 = 91.425 × 0.9 = **82.2825**。
2. **同类型的 Mod 元素先合并成一个槽位，再去配对。** 这是"火 + 火 + 毒 → 毒气"而不是"火 190 + 毒 180"的原因。

---

## 情形 1：只有一个元素 Mod（火）——不配对

**配置**：膛线（+165% 基伤）+ 地狱火（+90% 火）+ 玄骸火焰 50%

| 步骤 | 计算 | 结果 |
|---|---|---|
| 面板 | 冲击 7.13 + 穿刺 6.21 + 切割 9.66 | 23.00 |
| ① 玄骸 | 23.00 × 50% = 11.5 | 火 11.5 |
| ② 基伤 | ×(1+165%) = ×2.65 | 冲击 18.895 / 穿刺 16.456 / 切割 25.599 / **火 30.475** |
| ④ 火 Mod | 新面板总伤 91.425 × 90% | 火加量 **82.2825** |
| ⑤ 配对 | 火与面板火**同类型先合并** = 30.475 + 82.2825 | 火 **112.757**，无复合 |

**最终分布**：`冲击 18.895 / 穿刺 16.456 / 切割 25.599 / 火焰 112.757`，加成后总伤 **173.707**。

> **④ 的基数怎么来的**：①+② 之后的总伤 = 18.8945 + 16.4565 + 25.599 + 30.475 = **91.425**，
> 火 Mod 加量 = 91.425 × 90% = **82.2825**。
> ⚠ 这正是 **D-022 待你确认的点**：这里用的"新面板总伤"不含物理 %Mod（本例没有物理 Mod，所以看不出差别）。

---

## 情形 2：无玄骸 —— 对比玄骸贡献

**配置**：膛线 + 地狱火，**玄骸关掉**

| 步骤 | 结果 |
|---|---|
| 面板 → 基伤 ×2.65 | 18.895 / 16.455 / 25.599 = 60.949 |
| 火 Mod | 60.949 × 90% = **54.855** |
| 最终 | 火焰 54.855，总伤 **115.805** |

玄骸 50% 让总伤从 115.805 → 173.707（**×1.5**，因为玄骸在基伤之前，被 ×2.65 一起放大，见 D-017）。

---

## 情形 3：火 + 冰 → 爆炸

**配置**：膛线 + 地狱火（+90% 火）+ 低温弹头（+90% 冰）+ 玄骸火焰 50%

| 步骤 | 计算 | 结果 |
|---|---|---|
| ① 玄骸 | 同上 | 火 11.5 |
| ② 基伤 ×2.65 | 同上 | 合计 91.425 |
| ④ 元素加量 | 火 Mod = 91.425 × 90% = **82.2825**；冰 Mod = 91.425 × 90% = **82.2825** | |
| ⑤ 槽位 | 面板火 30.475 / Mod 火 82.2825 / Mod 冰 82.2825 | |
| ⑤ 先合并同类型 | 火 = 30.475 + 82.2825 = **112.757** | |
| ⑤ 配对 | 火 112.757 + 冰 82.2825 → **爆炸** | **195.040** |

**最终分布**：`冲击 18.895 / 穿刺 16.456 / 切割 25.599 / 爆炸 195.040`，总伤 **255.990**。

> 注意：面板火也被卷进了配对（面板火 + Mod 火先合并成 112.757，再整体与冰配对）。
> 这就是"**面板元素先入队**"的默认口径（A-02 的细问之一）。

---

## 情形 4：火 + 毒 → 毒气

**配置**：膛线 + 地狱火（+90% 火）+ 污染弹匣（+90% 毒）+ 玄骸火焰 50%

| 步骤 | 结果 |
|---|---|
| 元素加量 | 火 Mod 82.2825 / 毒 Mod 82.2825 |
| 先合并同类型 | 火 = 30.475（面板）+ 82.2825 = **112.757** |
| 配对 | 火 112.757 + 毒 82.2825 → **毒气 195.040** |
| 最终 | 总伤 **255.990**（与情形 3 相同量级，但复合类型不同） |

→ **毒气是 DoT 类型**（每秒 50% 基础伤害），爆炸不是（D-008：爆炸单列、不进 DoT）。

---

## 情形 5：玄骸火 + 冰 Mod → 爆炸（自带元素排槽位 9）

**配置**：膛线 + 低温弹头（+90% 冰）+ **玄骸火焰 50%**（无火 Mod）

| 步骤 | 结果 |
|---|---|
| 面板火（来自玄骸） | 11.5 × 2.65 = **30.475**，排在**槽位 9** |
| 冰 Mod | 91.425 × 90% = **82.2825**，排在**槽位 0** |
| 配对 | 冰（0）先入队，火（9）随后 → **爆炸 112.757** |
| 最终 | 总伤 **173.707** |

> **D-025**：武器自带元素（含玄骸）**排在 8 个 Mod 槽位之后**（槽位 9~12），
> 自带元素内部优先级 火 > 冰 > 电 > 毒。之前实现成 `order = -1000`（抢在最前）是错的。

---

## 情形 5b：玄骸火 + 火 Mod + 毒 Mod（顺序决定成败）

**配置**：膛线 + 地狱火 + 污染弹匣 + 玄骸火 50%

```
槽位 1  火 Mod  82.2825
槽位 2  毒 Mod  82.2825
槽位 9  玄骸火  30.475
```

| 步骤 | 结果 |
|---|---|
| 按槽位从小到大配对 | 火(1) + 毒(2) → **毒气 195.040** |
| 玄骸火(9) 随后并入**同类型**的火槽位 | 火已被转成毒气 → **全部成为毒气** |
| 最终 | `冲击 18.895 / 穿刺 16.456 / 切割 25.599 / **毒气 195.040**`，总伤 **255.990** |

> 若把自带元素排在最前面（错误实现），玄骸火会先跟火 Mod 合并，毒就被晾在一边，
> 结果变成"火 + 毒"分离 —— 这是 D-025 要修的问题。

## 情形 6：同类型两张 Mod 先合并

**配置**：膛线 + 地狱火（+90% 火）+ 野火（+60% 火）+ 玄骸火焰 50%

| 步骤 | 结果 |
|---|---|
| 元素加量 | 火 = 91.425 × (90% + 60%) = **137.1375** |
| 先合并同类型 | 火 = 30.475（面板）+ 137.1375 = **167.612** |
| 最终 | 火焰 167.612，总伤 **228.563** |

> **这就是 D-006 的核心**：两张火卡合成一个"火 137"槽位，而不是两个各自去找配对。
> 若面板有火且场上还有毒：火 30.475 + 137.1375 = 167.612 再与毒配对 → 毒气（而不是"火 + 毒气"混合）。

---

## 情形 7：复合元素 Mod（病毒/磁力二选一）

**配置**：膛线 + 生化弹药（+150% 病毒、+150% 磁力）+ 玄骸火焰 50%

| 步骤 | 结果 |
|---|---|
| 取哪个 | 只生效**第一个**（病毒），磁力被忽略（一条 Mod 不能同时给两种复合元素） |
| 元素加量 | 病毒 = 91.425 × 150% = **137.1375** |
| 配对 | 复合元素**不参与配对**；面板火 30.475 落单 |
| 最终 | `冲击 18.895 / 穿刺 16.456 / 切割 25.599 / 火焰 30.475 / 病毒 137.137`，总伤 **228.563** |

---

## 情形 8：物理 Mod 只放大自己，不进复合

**配置**：膛线 + 穿甲口径（+120% 穿刺）+ 地狱火（+90% 火）+ 玄骸火焰 50%

| 步骤 | 结果 |
|---|---|
| ③ 物理 % | 穿刺 6.21 × (1+120%) = **13.662** → 基伤后 = 13.662 × 2.65 = **36.204** |
| ④ 元素 % | 火 = 91.425 × 90% = 82.2825（基数**不受**穿刺加量影响，见 D-022） |
| 最终 | `冲击 18.895 / 穿刺 36.204 / 切割 25.599 / 火焰 112.757`，总伤 **193.455** |

> **这里就是 D-022 的分歧所在**：如果元素基数**含**物理 %Mod，火 Mod 加量会变成
> (91.425 + 13.662) × 90% = 94.578，总伤 205.751 而不是 193.455。
> **这就是需要你拍板的那一项。**

## 本轮发现并修复的 bug（重要）

写这些例子时发现 `pairOf()` 有 bug：配对表用**字面键**（`'heat+cold'`），
而查找时用 `[a, b].sort()` 拼 key —— 但 `'cold'` 的字典序在 `'heat'` 之前，
所以 `heat + cold` 实际拼成 `'cold+heat'`，**六种复合配对全部失效**。

后果：火 + 冰本应合成爆炸，实际算出"火 112.757 + 冰 82.282"两个未配对元素。

已修复（改为有序对表、双向匹配），并补了覆盖六种配对 × 两种顺序的测试。
**这类问题只有拿真实数据跑具体例子才会暴露**，所以本文件请当作回归基准保留。
