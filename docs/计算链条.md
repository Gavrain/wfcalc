# 计算链条 · 逐步中间值（附录）

> **先读 [`变量依赖图.md`](变量依赖图.md)** —— 那份讲「武器身上有哪些变量、谁是输入、谁是 computed」。
> 本文只做补充：把每一步的**实际数值**摊开，便于对照排查。
>
> 数据由 `node packages/demo/src/gen-chain.mjs <武器id> [--kuva <元素>] [--mods a,b,c]` 从真实内核导出。
>
> 两把对照武器，**装的 Mod 完全相同**：
> - **赤毒·卡拉克**（玄骸系，玄骸火 60%）
> - **螺钉步枪 Boltor**（非玄骸，同一流程但加成为 0）
>
> Mod：膛线 +165% 基伤、分裂膛室 +90% 多重、致命一击 +150% 暴率、
> 弱点感应 +120% 暴伤、地狱火 +90% 火。

## 链的总览

```
① 基础面板        Weapon + AttackMode          ← 武器自身的数
       │
       ▼
② 玄骸加成        applyKuvaBonus               ← 所有武器都走；非玄骸 amount = 0
       │
       ▼  新面板
③ 基伤 + 多重     applyBaseDamage / multishot
       │
       ▼
④ 元素/物理加量    applyElements(hit)           ← Mod 在这里进
       │   + 两两合成 mergePairwise
       ▼
⑤ 暴击 + 爆头     damageLine
       │
       ▼
⑥ 输出口径        buildOutput                  ← demo 右侧那 6 行
       │
       ▼
⑦ DoT            dotTick / dotSixSecondCurve
```

## ② 玄骸加成（**所有武器都走这一步**）

```
加成量 = 面板总伤 × 加成比例
新面板 = 面板 + { 玄骸元素: 加成量 }
```

这一步**与元素类型无关**——冲击、穿刺、切割、火、电…都走同一行代码，没有类型特判。

| | 赤毒·卡拉克（玄骸） | 螺钉步枪（非玄骸） |
|---|---|---|
| `active` | **true** | **false** |
| 元素 | heat | — |
| 比例 | 60% | 0 |
| **加成量** | `23 × 0.60 = 13.80` | **0** |
| 加成前 | 冲 7.13 + 穿 6.21 + 切 9.66 = **23** | 冲 2.5 + 穿 20 + 切 2.5 = **25** |
| **加成后（新面板）** | 冲 7.13 + 穿 6.21 + 切 9.66 + **火 13.80** = **36.80** | 与加成前**完全相同** = **25** |

**关键**：非玄骸武器不是「跳过」，而是「加成为 0 地走完」。
这样链条对每把武器都是同一条，排查时不会出现"这一段为什么没有了"。

> ⚠ **别把这一步的不变误读成"普通武器没有增益"**：非玄骸只有在**这一步**不变
> （它本来就没有玄骸加成），从 ③ 基伤开始每一层都照常吃增益：
> 螺钉步枪 25 → 66.25 → 125.875 → 219.0225。

> 玄骸元素与武器自带元素**同类型时直接合并**（如武器自带火 + 玄骸也选火）。
> 合并发生在面板层，之后作为**一个**变量参与后面的合成。

## ③ 基伤 + 多重

```
基伤系数 = 1 + Σ baseDamage% = 1 + 165% = 2.65
新面板每个类型 × 2.65
多重     = 1 + Σ multishot%  = 1 + 90%  = 1.90   ← 只算出一个数，到 ⑥ 才乘
```

| | 赤毒·卡拉克 | 螺钉步枪 |
|---|---|---|
| 基伤 % | 165% | 165% |
| 基伤系数 | 2.65 | 2.65 |
| 加成后总伤 | `36.80 × 2.65` = **97.52** | `25 × 2.65` = **66.25** |
| 多重 | **1.90** | **1.90** |

赤毒·卡拉克的分布：冲 18.8945 + 穿 16.4565 + 切 25.599 + 火 36.57 = **97.52**
（玄骸那 13.80 被一起放大成 36.57 → 这就是「玄骸吃基伤」）

螺钉步枪的分布：冲 6.625 + 穿 53 + 切 6.625 = **66.25**
（**非玄骸武器同样吃到基伤增益**：25 → 66.25）

## ④ 元素 / 物理加量 + 两两合成（Mod 在这里进）

```
元素基数 = ③ 的总伤（玄骸加成后的新面板 × 基伤）
某元素加量 = 元素基数 × Σ该元素%
```

**槽位**是整个第 ④ 步的核心数据结构：

| 来源 | 槽位号 `order` | 说明 |
|---|---|---|
| Mod 元素 | **0~7** | 按 Mod 放置顺序 |
| 武器自带元素 | **9~12** | 内部优先级：火 > 冰 > 电 > 毒 |
| 面板自带复合元素 | 接在后面 | 不参与配对 |

### 赤毒·卡拉克（上 `+90% 火`）

元素基数 = **97.52**，火 Mod 加量 = `97.52 × 0.90 = 87.768`

| order | 来源 | 类型 | 数量 |
|---|---|---|---|
| 4 | Mod | heat | **87.768** |
| 9 | 面板自带 | heat | **36.57** |

→ 同类型**先合并**：火 = 87.768 + 36.57 = **124.338**（无可配对对象，保持单元素）

最终命中分布：冲 18.8945 + 穿 16.4565 + 切 25.599 + **火 124.338** = **185.288**

### 螺钉步枪（上 `+90% 火`）

元素基数 = **66.25**（③ 的结果），火加量 = `66.25 × 0.90 = 59.625`

最终命中分布：冲 6.625 + 穿 53 + 切 6.625 + **火 59.625** = **125.875**

### 有复合元素时（示例）

面板自带毒素 10、玄骸选电 60% → 电加量 `10 × 0.60 = 6`，元素基数 = 10 + 6 = **16**。
上 `+90% 毒素 Mod` → 毒素加量 `16 × 0.90 = 14.4`，槽位为：

```
toxin@1(mod)=14.4    electric@9(panel)=6    toxin@10(panel)=10
   ↓ mergePairwise 第 1 步：同类型先合并（D-006 / C-10）
toxin=24.4           electric=6
   ↓ 第 2 步：两两配对
corrosive = 24.4 + 6 = 30.4        （产量规则见下方"待确认" D-074）
```

| 1（暴击） | 0.575 / 4.62 | 0.250 / 3.96 |

| 期望倍率 | 3.0815 | 1.74 |

## ⑦ DoT

```
DoT 基础值 = ③ 的总伤（**不含** ④ 的元素/物理 Mod 加量）× 期望倍率
```

| | 赤毒·卡拉克 |
|---|---|
| ④ 之前的分布（含玄骸、含基伤） | 冲 18.8945 + 穿 16.4565 + 切 25.599 + **火 36.57** = **97.52** |
| × 期望倍率 3.0815 | **300.5079** |
| 火焰每跳 | `300.5079 × 0.50 × (1+0.90)` = **285.4825** |
| 切割每跳 | `300.5079 × 0.35` = **105.1778** |

> **注意**：DoT 基础值里的火 36.57 **包含玄骸那份**（玄骸是武器固有不剔除），
> 但**不包含** ④ 里由 Mod 加进来的 87.768。
> 这正是需求方观察到的「DoT 基础值取的是没有元素 Mod 的那个值」——当前实现已经如此。
