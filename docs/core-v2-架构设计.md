# core v2 架构设计（草案）

> 只做设计，不写生产代码。1.0 收尾走 `release/1.0`，重写走独立分支。
> 口径依据见 [`核心事实.md`](核心事实.md)。

## 1. 目标与边界

- 只计算**武器自身的输出能力**；不做敌人克制、护甲、削甲、护盾、部位倍率（核心事实 §0）。
- 数据层与界面层**不动**：内核的公开 API 必须兼容数据层与界面已用的名字。

## 2. 总流水线

```
武器 + 模式 + 配装 + 上下文
        │
        ▼
① 场景 Scenario   数据层决定：不同射击模式 = 不同场景；场景内各段互不影响
        │
        ▼
② 素材池 Buckets  每个键 → 素材数组（不合并，每条带来源）
        │
        ▼
③ 派生 derive     只有"把某乘区的结果拿去生成另一乘区的加成"才需要（目前无真实数据）
        │
        ▼
④ 口径 Calibers   每个口径自己决定怎么从素材取用、是否调用别的口径
        │
        ▼
⑤ 汇总            各口径最终值 + 素材池快照（供验证页与拆解）
```

**分工一句话**：桶只提供素材，口径只读取素材。

## 3. 场景（Scenario）

- **由数据层决定**：数据层把武器的模式、变体、段都拆好了，内核收到即用。
- 一个模式内不管几段，都算**一个场景**；不同射击模式才是不同场景。
- 场景携带**上下文**：派系、玄骸、爆头开关、叠加层数 y、目标异常种类数 a、连击倍率、爆发层数、窗口秒数。
  这些**不是由数据导出的**，因此不进素材池。
- 界面层负责把多个场景分别渲染。

## 4. 素材桶（Buckets）

```ts
interface BucketEntry {
  value: number;                      // 百分比口径（基伤 165 = +165%）
  form: 'pct' | 'flat' | 'mul';
  from: EntryFrom;                    // 必填：这条素材从哪来
  flags?: { heavyX2?: true };         // 只有少数素材需要（数据给的结构化标记）
}
type Bucket = { key: string; entries: BucketEntry[] };   // 只追加，永不覆盖
```

- 每个键都是**数组**：基伤 Mod 与镀层基伤 Mod 是两条素材，不合并。
- 来源可递归追溯（`derived` 带原来源），所以"这个数怎么来的"= 渲染素材池，不用重算。

| 类别 | 键（示例） |
|---|---|
| 面板 | `panel.critChance`、`panel.multishot`…（面板是单一事实，不是数组） |
| 加成 | `baseDamage`、`multishot`、`critChance`、`critMultiplier`、`statusChance`、`statusDamage`、`fireRate`、`magazine`、`reloadSpeed`、`ammoEfficiency`… |
| 条件基伤 | `co`（每层值）、`coFreeze` |
| 元素 / 物理 | `elemental:heat`…、`physical:slash`… |
| 派系 | `faction:grineer`… |
| 独立乘区 | `finisherDamage`、`slamDamage`、`bodyshotDamage`、`bladeShadow`、`weakpointCritChance` |
| 派生 | `baseDamage#passive`（被动基伤，按每段面板分布平摊） |

## 5. 条件判断写在内核，不做规则表

能直接放进乘区里判断的，都直接写在内核：

| 情况 | 写法 |
|---|---|
| 弱点暴击率只在开爆头时计入 | 算暴击率时先看爆头开关，再决定是否把弱点暴击率并进同一个括号 |
| 弱点伤害与爆头伤害 | 算爆头倍率时两个键放进同一个括号 |
| 重击 ×2 | 看数据给的 `heavyX2` 标记，重击模式时再算一份 |
| 震地伤害只对震地生效 | 看模式标记 |

不引入通用钩子，也不把条件写成数据里的 `+xx% cc when …`——自然语言写的条件存在歧义，不作为实现依据（核心事实 §12）。

**唯一需要单独"派生"步骤的**，是"把某乘区的结果拿去生成另一乘区的加成"（例：暴击率的 30% 加到触发率，封顶 40%）。目前没有真实数据用到它，**到那时再定放在哪**，架构里不预留空壳。

## 6. 口径（Calibers）

每个口径自己重写：怎么从素材取用、是否调用其他口径，都由各自逻辑决定，不在规则层约定。

初步清单：单弹头 / 单次射击 / 连发秒伤 / 续航秒伤 / 异常加权单层秒伤 / N 秒异常总伤 / N 秒总伤 / 稳态秒伤。

口径只读素材池，不写素材池。

## 7. 实时展示桶的验证页

- 新页面 `packages/demo/public/core-inspector.html` + `core-inspector.js`（零依赖，沿用现有 demo 服务）；
- 数据来自内核导出的**素材池快照**（`evaluate()` 返回值里带 `buckets`），页面不重算；
- 每行：键 / 类型 / 值 / 来源（Mod 名、槽位）/ 是否派生；按场景分组并排显示；
- 选武器、拖 Mod 时自动刷新。

**先做这个页面**：它是评审架构与重写期间唯一需要的人工验证工具。

## 8. 与旧内核的对照

| 旧（v1） | 新（v2） |
|---|---|
| `Contribution[]` 扁平数组 | 场景 + 分键素材池（数据层仍产出 `Contribution`，由 `collect()` 分键） |
| `weapon-state` 快照 | 场景素材池快照（界面读快照改成读素材池，字段名尽量不变） |
| 界面层 30+ 个"去掉重算"函数 | 统一 `evaluate()` + `withSourceRemoved()`（两遍计算法） |
