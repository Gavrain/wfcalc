# 变量依赖图（武器身上有哪些变量、谁从谁算出来）

> 核心原则：**每个量只算一次，算完就是一个 computed；下游直接取用，不重算。**
>
> ```
> ✗ 错误做法：暴击乘区自己从「面板暴率 + Mod」再算一遍
> ✓ 正确做法：暴击乘区直接读 w.当前暴击率
> ```
>
> 类比前端：`w.面板.暴击率`、`w.暴击率%Mod`、`w.暴击率绝对加成` 是 **data**，
> `w.当前暴击率` 是 **computed**（依赖上面三者），暴击乘区是**消费者**。
>
> 数据由 `node packages/demo/src/gen-graph.mjs <武器id> [--kuva <元素>]` 从真实内核导出。
> 例：`npm run report:graph -- KuvaKarak --kuva heat`

---

## 一、武器对象 `w` 上的两棵树

```
w
├── 面板.*                  输入的原子值（来自数据层 generated/）
└── <属性>%Mod / <属性>绝对加成 / <属性>乘算      输入的 Mod 列表（来自 mods.json）
        │
        ▼  computed
└── 当前<属性>              = f(面板, %Mod, 绝对加成, 乘算)
        │
        ▼  被下游直接取用
   暴击乘区 / 输出口径 / DoT …
```

**「当前某属性」永远是 computed，不是输入。** 暴击乘区只读它，不再碰面板和 Mod。

```ts
// 示例：多重
w.面板.多重        = 15          // Twin Rogga，武器自带
w.多重%Mod         = [split_chamber: +90%]
w.当前多重         = 15 × 1.9 = 28.5     ← 下游（单次射击）直接读这个
```

## 二、输入层（不可再分）

### 2.1 武器面板（派生自 `AttackMode`，模式 override 优先）

| 变量 | 类型 | 卡拉克 | 螺钉步枪 | 说明 |
|---|---|---|---|---|
| `w.面板.伤害分布` | **`Record<DamageType, number>`** | 冲 7.13 / 穿 6.21 / 切 9.66 | 冲 2.5 / 穿 20 / 切 2.5 | **不是一个数，是数组** |
| `w.面板.暴击率` | number | 0.23 | 0.10 | |
| `w.面板.暴击伤害` | number | 2.10 | 1.80 | |
| `w.面板.触发率` | number | 0.31 | 0.14 | |
| `w.面板.射速` | number | 11.6667 | 8.75 | |
| `w.面板.弹匣` | number | 70 | 60 | |
| `w.面板.装填时间` | number | 1.7 | 2.6 | 是**时间**，不是速度 |
| `w.面板.多重` | number | 1 | 1 | **武器自带多重，不是常量 1** |

> `w.面板.伤害分布` 是整条链的起点，**始终是「类型 → 数值」的映射**，
> 不是单个数字。后面每一步都保持这个形状。
>
> ⚠ **`w.面板.多重` 不能写死成 1**：57 把武器自带多重
> （Twin Rogga **15**、Brakk / Tenet Detron / Drakgoon **10**、Boar **8**…）。
> 之前内核从常量 `1` 起算，Twin Rogga 的单次射击少了 **15 倍**，已修复
> （`docs/decisions.md` D-076，回归测试 `multishot-panel.test.ts`）。

### 2.2 Mod 层（**每类属性拆成三格，各自是数组**）

对应你说的「`w.暴击率mod` / `w.绝对值暴击率`」——它们本来就是两类不同的东西：

| 变量 | 类型 | 卡拉克 | 螺钉步枪 |
|---|---|---|---|
| `w.暴击率%Mod` | `{src, amount}[]` | `[point_strike:150]` | `[point_strike:150]` |
| `w.暴击率绝对加成` | `{src, amount}[]` | `[]` | `[]` |
| `w.暴击伤害%Mod` | `{src, amount}[]` | `[vital_sense:120]` | `[vital_sense:120]` |
| `w.暴击伤害绝对加成` | `{src, amount}[]` | `[]` | `[]` |
| `w.基伤%Mod` | `{src, amount}[]` | `[serration:165]` | `[serration:165]` |
| `w.多重%Mod` | `{src, amount}[]` | `[split_chamber:90]` | `[split_chamber:90]` |
| `w.触发率%Mod` | `{src, amount}[]` | `[]` | `[]` |
| `w.射速%Mod` | `{src, amount}[]` | `[]` | `[]` |
| `w.元素%Mod` | `{stat, src, amount}[]` | `[elemental:heat ← hellfire:90]` | 同左 |
| `w.物理%Mod` | `{stat, src, amount}[]` | `[]` | `[]` |
| `w.玄骸加成` | `{element, ratio}` | `{heat, 0.6}` | **`{null, 0}`（仍然存在）** |

> **为什么是数组**：同一个属性可以有好几张 Mod（两张暴率 Mod、三张火 Mod），
> 数组保留每一张的来源，才能在做「逐乘区拆解」时说清是谁贡献了多少。
>
> **为什么玄骸对非玄骸武器也存在**：值写成 `{element: null, ratio: 0}`，
> 而不是「没有这个变量」。这样**每把武器都走同一条链**，不会出现"这段为什么跳过了"。

## 三、computed 层（谁依赖谁）

每个 computed 只依赖上游，**下游不再回头重算**。

| computed | 公式 | 依赖 |
|---|---|---|
| `w.当前暴击率` | `(面板暴击率 × (1 + Σ暴击率%Mod) + Σ暴击率绝对加成) × Π乘算` | 面板暴击率、暴击率%Mod、暴击率绝对加成 |
| `w.当前暴击伤害` | `(面板暴击伤害 × (1 + Σ暴伤%Mod) + Σ暴伤绝对加成) × Π乘算` | 面板暴击伤害、暴伤%Mod、暴伤绝对加成 |
| `w.当前触发率` | `面板触发率 × (1 + Σ触发率%Mod)` | 面板触发率、触发率%Mod |
| `w.当前射速` | `面板射速 × (1 + Σ射速%Mod)` | 面板射速、射速%Mod |
| `w.当前多重` | **`面板多重 × (1 + Σ多重%Mod) + Σ绝对值`** | 面板多重、多重%Mod |
| `w.新面板` | `面板.伤害分布 + {玄骸元素: 面板总伤 × 比例}` | 面板.伤害分布、玄骸加成 |
| `w.基伤面板` | `新面板.每一型 × (1 + Σ基伤%Mod)` | **新面板**、基伤%Mod |
| `w.元素槽位` | 各元素独立成槽（Mod 序 0~7、自带 序 9~12） | 基伤面板、元素%Mod、物理%Mod |
| `w.命中分布` | 槽位两两合成 → 复合/单元素 | 元素槽位 |
| `w.命中期望` | `命中分布.合计 × 期望暴击倍率(当前暴击率, 当前暴击伤害)` | 命中分布、**当前暴击率**、**当前暴击伤害** |
| `w.单次射击` | `命中期望 × 当前多重` | 命中期望、**当前多重** |

### 两个关键点（对应你提的写法）

**1. 暴击乘区读 `w.当前暴击率`，不重算**

```
✗ 暴击时：critChanceTotal() 又去读 weapon.critChance 和 mods 重算一遍
✓ 暴击时：直接用 w.当前暴击率   ← 已经在 computed 层算好了
```

**2. 基伤直接用 `w.新面板`，不再叠玄骸**

```
✗ 基伤时：applyBaseDamage(panelWithKuva, …)  ← 又调了一次玄骸
✓ 基伤时：applyBaseDamage(w.新面板, 基伤%Mod) ← 新面板是现成的 computed
```

### 值是「数组」的两处

| computed | 形状 | 为什么 |
|---|---|---|
| `w.新面板` | `{类型: 数值}` | 基础面板本来就有好几种元素 |
| `w.元素槽位` | `Array<{type, order, source, amount}>` | 每个元素各占一槽，**合成前不合并** |

## 五、复合元素合成（在 `w.元素槽位` → `w.命中分布` 这一步）

配对表（`PAIR_LIST`）：

| 组合 | 结果 | 组合 | 结果 |
|---|---|---|---|
| 火 + 冰 | **爆炸** blast | 冰 + 毒 | **病毒** viral |
| 火 + 毒 | **毒气** gas | 冰 + 电 | **磁力** magnetic |
| 火 + 电 | **辐射** radiation | 毒 + 电 | **腐蚀** corrosive |

流程：

```
1. 同类型先合并（D-006）
     火Mod 87.768 + 自带火 36.57 → 火 124.338
2. 按 order 从小到大两两配对
     若还有电 6 → 火 124.338 与电 6 配成辐射
3. 配对产量 = a + b（当前口径，见校验例 2「毒素64 + 火10 → 毒气74」）
```

**自带元素在合成前是独立槽位**，这正是你要求的行为：
面板 100 冲 + 60 火、上 `+100% 火 Mod` 时，合成前是 `heat@0(mod)=160` 与 `heat@9(panel)=60`
两个槽，到这一步才合并成 220。

## 六、DoT 取的是哪个 computed

```
w.DoT基础值 = w.基伤面板.合计 × 期望暴击倍率(当前暴击率, 当前暴击伤害)
```

注意它取自 **`w.基伤面板`**（玄骸已进、元素 Mod **未进**），
而不是 `w.命中分布`。这就是「DoT 基础值不含元素 Mod」在依赖图上的体现——
它依赖的是链条中间那个 computed，不是末端那个。

## 七、实现状态（D-075 已落地）

`packages/core/src/weapon-state.ts` 已按本图实现，`compute()` 返回 `state`。

```ts
const res = compute(weapon, mode, contribs, options, beam);
res.state.inputs     // 输入的原子值 + 各 Mod 数组
res.state.computed   // 当前<属性> / 新面板 / 基伤面板 / 元素槽位 / 命中分布
res.state.buckets    // 每个乘区的 Σpct / Σflat / Πmul / 贡献者
```

| 图上要求 | 状态 |
|---|---|
| 暴击乘区读 `w.当前暴击率` | ✅ 集中在 `state.buckets`，`panelPairs` 直接读 computed |
| 基伤直接用 `w.新面板` | ✅ `state.computed.新面板`（数组形态，可见可验证） |
| `w.玄骸加成` 对非玄骸也存在 | ✅ `{ type: null, ratio: 0 }`，始终在 `inputs` 里 |
| `w.当前<属性>` 作为一等公民 | ✅ `state.computed.当前*` |
| 面板多重取面板值 | ✅ `state.inputs.panel.multishot` → `state.computed.当前多重` |
| **每段各有 computed** | ✅ `res.perSegment[]`，与 `res.segments[]` 一一对应 |

**安全网**（`weapon-state.test.ts`，14 项）：
- 8 组配装（面板多重 1 / 15 × 4 种配装）断言 `state.computed` 与结算链逐位相等；
- 4 项多段武器用例：`perSegment` 覆盖、逐段与 `segments` 一致、多段合计 = `totalSpread`；
- 2 项镀层用例（做过反向验证：回退修复后确实失败）。
另有 `multishot-panel.test.ts` 6 项锁住面板多重。

> **`resolveSegment()` 是什么**：结算**一个伤害段**。多段武器（60 把，如 Astilla Prime 的
> impact / attack / explosiveAttack / embedDeathAttack）每段是独立伤害向量。
>
> **不再重复计算**：`compute()` 先为每段算一次上游 computed，逐段结算与 `state`/`perSegment`
> **共用同一份**；`resolveSegment(ctx, seg, upstream?)` 收到上游就直接取，不再重跑玄骸/基伤。
> 单独调用 `resolveSegment(ctx, seg)`（不传 upstream）仍然可用。
>
> 外部一律读 `state`（主段）或 `perSegment[i]`（逐段），不要再自己从面板 + Mod 重算。
