## 2. 为什么 `behaviours` 不能当成面板

`damagePerShot[20]` 与顶层 `totalDamage` **总是**对应游戏面板（Braton = 24）。
`behaviours[]` 是引擎里的攻击定义，**可能带一堆面板上根本看不到的段**：

| 武器 | 导出 `totalDamage`（= 游戏面板） | `behaviours` 里的段 | 说明 |
|---|---|---|---|
| Braton | **24**（`7.92 / 7.92 / 8.16`，12% 暴 1.6× 6% 触发） | 第 1 条是面板；第 2 条 `20 / 2 / 28`、触发 12% | 第 2 条是别的模式的残留 |
| Astilla Prime | **240** | 直击 70 + 爆炸 `42+78`（=120）= 190，还另有一段 | 面板和段之和不等 |
| Gorgon（HeavyRifle） | **25** | 首段 `18.75 / 3.75 / 2.5` ✅ | 这把是对得上的（样本） |

实测：661 条有 `behaviours` 的武器里，`behaviours[0]` 各段之和与 `damagePerShot` 之和
**一致 415 条、不一致 239 条、首段无伤害 7 条**。

这个现象**已经吃过一次亏**：`docs/decisions.md` D-015 记着「Braton 数据里出现两个完全不同的模式」，
而第二个模式的实际数值与游戏面板对不上——它就是 `behaviours[1]` 那条 `20 / 2 / 28` 被当成独立模式收了进来。

→ 因此**面板 = 顶层字段**，`modes[].variants` = 参与计算的伤害结构，两者语义不同，应当分开对待（D-139 Q1）。

## 8. 由这批更正得出的新结论（会改写 D-139）

1. **导出顶层字段 ≠ 游戏面板**。至少 4 把对不上：
   - 类型错：两把重力奇点，导出写病毒，游戏是**磁力**；
   - 数值错：月神狩弓导出 75，游戏 240（比例 1:1）；
   - 结构错：蕈菇游戏是「直接命中 16 + 范围 114」，导出塌成一条 `DT_EXPLOSION 130`。
2. **`damagePerShot` 的索引含义也要再核**：两把重力奇点的 240 / 200 在游戏里应是磁力，
   导出却落在 `DT_VIRAL` 位置；`DT_EXPLOSION` 落在第 8 位。`clean.ts` 的 `DAMAGE_PER_SHOT_INDEX`
   需要对照这几把重新验一遍。
3. 对这批 17 把，「面板能不能一致」**不能一概而论**：3 把近战、预言者、分离两把是导出对的；
   蕈菇、两把重力奇点、月神狩弓需要人工值。
