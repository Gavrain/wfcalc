## 主要内容

### 1. 素材池（内核）

新增 `core/src/material.ts`：把输入的贡献**按乘区键分组**，并给出每个键的汇总。

```ts
compute(...).materials = {
  buckets: [ { key: 'baseDamage', entries: [...], total: { pct: 330, ... } } ],
  input: { kuva: { type, ratio, amount, segments } },
  check: { ok, inputCount, bucketedCount, badBuckets },
}
```

**结构分两层**：

| 层 | 内容 | 说明 |
|---|---|---|
| **input**（输入层） | 玄骸元素加成 | 改的是**面板本身**，在所有乘区之前 |
| **buckets**（各乘区） | Mod / 赋能 / 套装 | 都建立在加成后的面板上 |

**自检**：逐个乘区核对「汇总 = 各素材之和」，对不上会列出 `badBuckets`。

> 注意不能把不同乘区的百分比相加——基伤与触发率是两个乘区，加出来没有意义。

### 2. 验证页 `core-inspector.html`

零依赖，沿用现有 demo 服务。访问：

```
npm run demo
→ http://127.0.0.1:5178/check
```

**功能**：

- 武器 / 模式 / 异况种类 / 镀层叠层 / 连击倍率
- 8 个 Mod 槽 + 劣化槽 + 赋能槽（支持拖动、拖出卸下、一键全卸）
- Mod 与赋能分栏，卡片式多列显示，每个词条值单独一行
- 配装存 `localStorage`，刷新不丢
- 右侧实时显示素材池，含每个乘区的汇总与来源

**默认值**：

| 项 | 默认 |
|---|---|
| 异况种类 | 内核按当前命中分布数出 |
| 镀层叠层 | 满层（该卡自己的叠层上限） |
| 连击倍率 | 12（仅近战可改） |
| 玄骸元素 | 火 |

### 3. 套装效果只留一份实现

新增 `core/src/set-bonus.ts`，主界面与验证页都调它。

内核只认「套名 → 张数」这个纯数据——**调用方各自数件数**（它本来就知道自己装了哪些卡）。

```ts
setBonusContributions({ counts: { vigilante: 3 }, comboMultiplier: 12 })
```

> 四套里只有**牺牲**需要知道套内张数（×1.25 放大本套其他卡）；私法 / 混沌 / 角斗士都是每张卡各算各的。

### 4. 劣化卡可以装进普通槽

以前 `slotAcceptsMod` 直接拒绝所有劣化卡进普通槽。需求方 2026-11-18 确认游戏内规则是：

- **劣化卡 → 普通槽、劣化槽 都能装**
- **普通卡 → 只能进普通槽**

两个方向都补上了判定。

### 5. 玄骸武器默认火

功能页打开玄骸武器时，玄骸元素以前显示「无」，现在默认显示「火」。

原因：`restoreLoadout` 里"先回默认"的默认值一律是 `none`，但玄骸武器本身自带一个元素加成。

## 已知限制

1. **素材池只服务展示**——计算路径仍读 `Contribution[]`，没有改成读素材池（那是 v2 的下一步）。
2. **武器自带元素不进素材池**——它属于基伤面板（需求方 2026-11-18 确认）。
3. 验证页只覆盖"看"，不含增幅计算（那在主界面）。
