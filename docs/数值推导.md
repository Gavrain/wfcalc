# 数值推导：武器变量 + Mod → demo 展示的每个数字

> 这份文件回答一个问题：**demo 界面上那个数字，是怎么从武器面板和 Mod 算出来的？**
>
> 所有数字都由 `packages/demo/src/gen-derivation.mjs` 从**真实内核 + 真实数据**跑出，
> 与 `verify-karak.mjs` 的手算逐位一致。内核改动后重跑该脚本即可核对哪些数字过期。
>
> 示例配装：**赤毒·卡拉克**（暴率 23% / 暴伤 ×2.1 / 触发 31% / 射速 11.667 / 弹匣 70 / 装填 1.7s）
> 面板 7.13 冲击 + 6.21 穿刺 + 9.66 切割 = **23**
> Mod：膛线 +165% 基伤、分裂膛室 +90% 多重、致命一击 +150% 暴率、弱点感应 +120% 暴伤、地狱火 +90% 火
> 外部：玄骸火焰 50%、无派系、不爆头

---

## 〇、先看这张表：demo 上每个区域由什么算出来

| demo 界面区域 | 展示的内容 | 计算公式入口 | 本文小节 |
|---|---|---|---|
| 左侧「基础面板 / 当前面板」 | 暴率、暴伤、触发、多重、射速、弹匣、装填 | `compute().panelPairs`，每行一个 `BUCKET` | §三 |
| 左侧「伤害分布」表 | 每种类型的伤害 + 触发率列 | `segments[].finalHit`（伤害）/ `总触发率 × 占比`（触发率） | L3 / L7 |
| 左上角「加成后总伤」 | 单弹头合计 | `spreadTotal(finalHit)` | L3 |
| 右侧「输出口径」列表 | 6 个伤害量 | `buildOutput().lines` | L6 |
| 右侧「异常状态伤害」 | 每种 DoT 的每层秒伤与层数 | `dotPerType` / `stacksPerType` | L7 |
| 右侧「爆炸异常」 | 每层伤害、是否触发范围伤害 | `blastDetail()` | L7 末尾 |
| 备选区「增幅」 | 每张候选 Mod 的 +x% | `gainsFor()` | §五 |
| 模式切换栏 | 同一把武器的不同 `AttackMode` | `panelStats(weapon, mode)` | L0 |

**一句话**：demo 不自己算任何东西，所有数字都是 `packages/core` 的
`compute()` 返回值按上表映射到界面。

## 一、两类输入

demo 的计算输入只有两类，全部摊平成同一张贡献表：

```
输入 A：武器        Weapon + AttackMode          ← 来自 packages/data/src/generated/
输入 B：Mod/赋能     Contribution[]                ← 来自 mods.json / arcanes.json，经 adapter 转换
```

### A. 武器提供了哪些变量

| 变量 | 含义 | 本武器取值 | 参与哪一步 |
|---|---|---|---|
| `mode.segments[].damage` | 该段伤害分布 | 见 L0 | ① 起点 |
| `weapon.critChance` | 面板暴率 | 0.23 | ⑤ 暴击 |
| `weapon.critMultiplier` | 面板暴伤 | 2.1 | ⑤ 暴击 |
| `weapon.statusChance` | 面板触发率 | 0.31 | ⑦ 触发 |
| `weapon.fireRate` | 面板射速 | 11.6667 | ⑧ 输出 |
| `weapon.magazineSize` | 弹匣 | 70 | ⑧ 持续伤害 |
| `weapon.reloadTime` | 装填**时间** | 1.7 | ⑧ 持续伤害 |
| `mode.multishot` | 面板多重 | 1 | ② 多重 |
| `mode.segments[].procChance` | **该段**触发率 | 0.31 | ⑦ 触发 |
| `mode.override` | 模式级面板覆盖 | 无 | 有则**优先于**武器级（D-050） |

> `mode.bullets`（导出里的 fireIterations）**不参与伤害计算**，只做溯源（C-12）。

### B. Mod 提供了哪些变量

每个 Mod 先摊成 `Contribution`，只有四个字段有意义：

```
{ stat, form, amount, scope }
   stat   加哪个属性（是乘区的钥匙）
   form   'pct' 百分比加算 | 'flat' 绝对值加算 | 'mul' 独立乘算
   amount 百分比口径（165 = +165%）
   scope  'hit' | 'dot' | 'both'
```

本配装摊开后：

| Mod | stat | form | amount |
|---|---|---|---|
| 膛线 | `baseDamage` | pct | 165 |
| 分裂膛室 | `multishot` | pct | 90 |
| 致命一击 | `critChance` | pct | 150 |
| 弱点感应 | `critMultiplier` | pct | 120 |
| 地狱火 | `elemental:heat` | pct | 90 |

## 二、一条链：从面板到 demo 的每个数字

```
        ┌── 输入 A：武器面板                      ┌── 输入 B：Mod 贡献表
        ▼                                         ▼
  L0 取段 ──► L1 玄骸 ──► L2 基伤 ×多重 ──► L3 元素加量/合成 ──► L4 暴击×爆头
                                                                    │
                            ┌───────────────────────────────────────┤
                            ▼                                       ▼
                     L5 命中分布（finalHit）                 DoT 基础值（dotBase）
                            │                                       │
                            ▼                                       ▼
                     L6 五个输出口径 ◄────────────────── L7 DoT 每跳/叠层/六秒曲线
```

### L0 · 取段（起点）

`resolveSegment()` 只处理**一个** `DamageSegment`：

```
panel = { impact: 7.13, puncture: 6.21, slash: 9.66 }        合计 23
```

### L1 · 玄骸（在基伤之前）

```js
// applyKuvaBonus
augment = spreadTotal(panel) × kuva.ratio = 23 × 0.5 = 11.5
panelWithKuva = { ...panel, heat: 11.5 }                     合计 34.5
```

**这是 demo「触发率 / 伤害分布」列里出现火的原因**——火不是武器自带的，是玄骸给的。

### L2 · 基伤 × 多重

```js
// applyBaseDamage： g = 1 + Σ baseDamage% = 1 + 1.65 = 2.65
baseAfterBaseDamage = panelWithKuva × 2.65
                    = { impact 18.8945, puncture 16.4565, slash 25.599, heat 30.475 }   合计 91.425

// multishot： 1 + Σ multishot% = 1 + 0.90 = 1.90
```

- 玄骸那 11.5 被一起放大到 30.475 —— 这就是「玄骸吃基伤」（C-16）。
- **多重在这里只算出一个数，不参与加法**，要到 L6 才乘上去（C-01 / C-12）。
- 镀层类（`co`）会额外进基伤括号，但**不吃 AoE 段**。

### L3 · 元素加量 + 两两合成

```js
// 元素 % 的基数 = 玄骸加成后的新面板总伤（不含物理 % 的加量）
tNew = 91.425
heat加量 = tNew × Σ elemental:heat% = 91.425 × 0.90 = 82.2825
```

槽位（`order` 决定配对顺序）：

| order | source | type | amount |
|---|---|---|---|
| 4 | mod（地狱火） | heat | 82.2825 |
| 9 | panel（玄骸火） | heat | 30.475 |

同类型**先合并**（C-10），再配对；这里只有火一种元素，无需配对：

```
finalHit = { impact 18.8945, puncture 16.4565, slash 25.599, heat 112.7575 }   合计 173.7075
                                         ↑ 82.2825 + 30.475
```

> 若有第二张基础元素（如毒），火会与毒配成**毒气**，合成物不再参与配对。
> 自带元素排槽位 **9~12**，永远排在 8 个 Mod 槽位**之后**（C-19）。

### L4 · 暴击与爆头

```js
// 乘区骨架： (面板 × (1+Σpct) + Σflat) × Πmul
cc = 0.23 × (1 + 1.50) = 0.575
cd = 2.10 × (1 + 1.20) = 4.62

// damageLine：分档
k = floor(0.575) = 0,  f = 0.575
  第 0 档：概率 1−f = 0.425，倍率 1 + 0×(cd−1) = 1
  第 1 档：概率 f   = 0.575，倍率 1 + 1×(cd−1) = 4.62

非暴击 = 173.7075
暴击   = 173.7075 × 4.62 = 802.5287
期望   = 0.425 × 173.7075 + 0.575 × 802.5287 = 535.2797
```

期望倍率 `= 1 + cc(cd−1) = 1 + 0.575×3.62 = 3.0815`。

爆头是**独立开关**：`爆头且暴击 = 爆头倍率 × 暴击倍率 × 2`，那个 ×2 只作用于暴击那一档（C-15）。

### L5 · DoT 基础值

```js
// 剔除元素/物理 Mod 加量（走 side='dotBase'），但保留玄骸、基伤、多重
// 玄骸是武器固有属性 → **保留**（C-11 / D-008）
dotBaseRaw = baseAfterBaseDamage（原样，不含元素 Mod 加量）
           = { impact 18.8945, puncture 16.4565, slash 25.599, heat 30.475 }   合计 91.425

dotBase = dotBaseRaw × 期望倍率 3.0815
        = { impact 58.2234, puncture 50.7107, slash 78.8833, heat 93.9087 }    合计 281.7261
```

注意 `dotBase` 里的 heat 93.9087 = **玄骸那份 11.5 × 2.65（基伤）× 3.0815**，
即玄骸既吃基伤、又被暴击期望放大——这正是「玄骸保留」的体现。

**关键点**：每跳的基础值取的是**全类型之和** 281.7261，不是该元素自己那一份。
（早期 bug：取 `dotBase[该元素]` 会让完全由 Mod 合成的毒气恒为 0。）

### L6 · 五个输出口径（demo 右侧那 6 行）

| demo 行 | 公式 | 数值 |
|---|---|---|
| 单弹头 | `line.average`（已含暴击期望，**不乘多重**） | **535.2797** |
| 单次射击 | 单弹头 × 多重 = 535.2797 × 1.90 | **1017.0314** |
| 爆发伤害 | 单次射击 × 射速 = 1017.0314 × 11.6667 | **11865.3997** |
| 持续伤害 | 单次 × 弹匣 ÷ (弹匣÷射速 + 装填) | **9245.7602** |
| DoT 加权每层秒伤 | Σ(单层每跳 × 该类型占比)，**不含**层数/射速/多重 | **236.3645** |
| 六秒异常状态总伤 | 逐秒曲线累加（毒气封顶 10 层、火焰递增）＋爆炸 | **27167.2624** |

持续伤害：`1017.0314 × 70 ÷ (70 ÷ 11.6667 + 1.7) = 9245.7602`
（弹匣、装填吃 Mod：`magazine` 是容量 %，`reloadSpeed` 是速度 %，时间 = 面板 ÷ (1+Σ速度%)）

### L7 · DoT 每跳 / 叠层

```js
// dotTick： ① 基础值 × 系数 × (1+该类型元素%) × (1+异常状态伤害%) × (1+派系%)
heat.tick   = 281.7261 × 0.50 × (1+0.90) × 1 × 1 = 267.6398   ← 火吃自己那 +90% 火
slash.tick  = 281.7261 × 0.35 × 1        × 1 × 1 = 98.6041
toxin/electric/gas = 281.7261 × 0.50 = 140.8631   ← 配装里没有，**不参与**
```

```js
// 加权每层秒伤（D-061：分母只算有 DoT 的五种类型，冲击/穿刺不参与摊薄）
有DoT类型合计 = heat 112.7575 + slash 25.599 = 138.3565
heat 占比  = 112.7575 ÷ 138.3565 = 0.8150
slash 占比 =  25.5990 ÷ 138.3565 = 0.1850
236.3645 = 267.6398 × 0.8150 + 98.6041 × 0.1850
```

```js
// 每秒叠层 = 总触发率 × 元素占比 × 多重 × 射速
// ⚠ 这里的「元素占比」分母是**全分布**（触发池含所有伤害类型，§0.3 ②）
stack 分母 = 173.7075（整个 finalHit）
heat 占比  = 112.7575 ÷ 173.7075 = 0.6491
slash 占比 =  25.5990 ÷ 173.7075 = 0.1474
stacksPerSecond(heat)  = 0.31 × 0.6491 × 1.90 × 11.6667 = 4.4606
stacksPerSecond(slash) = 0.31 × 0.1474 × 1.90 × 11.6667 = 1.0127
```

> **两种分母是不同的口径**（D-061 明确）：加权每层秒伤只分配「本该产生 DoT 的那部分」，
> 所以分母是有 DoT 的类型之和；而叠层出自**触发池**，触发池包含冲击/穿刺，
> 所以分母是全分布。同一个「占比」二字，在两处含义不同。

### 爆炸异常（独立机制，D-031）

本配装**没有爆炸元素**（只有火，没有冰/电合成），所以爆炸不触发：

```
hasDotElement(finalHit, 'blast') = false  →  blastStacks = 0  →  不计入任何口径
```

配上冰（火+冰→爆炸）后，口径是：

```
每层伤害 = 基础值 × 0.3 × (1+派系%) × 异常伤害% × 暴击伤害 × 伤害弱点
满 10 层 → 每层系数 0.3 换成 3，并对周围 5 米产生范围伤害（单列，不进 DoT 合计）
```

> 注意满层是「**系数从 0.3 换成 3**」，不是「再乘 3 倍」（C-17）。

## 三、面板对照表（demo 左侧「基础面板 / 当前面板」）

demo 这张表直接来自 `res.panelPairs`，每一行都是同一句乘区骨架：

| 属性 | 基础面板 | 当前面板 | 推导 |
|---|---|---|---|
| 暴击几率 | 0.23 (23%) | 0.575 (57.5%) | `0.23 × (1+1.50)` |
| 暴击伤害 | ×2.1 | ×4.62 | `2.1 × (1+1.20)` |
| 触发几率 | 31% | 31% | 无触发 Mod |
| 多重射击 | 1.00 | 1.900 | `1 × (1+0.90)` |
| 射速 | 11.667 | 11.667 | 无射速 Mod |
| 弹匣容量 | 70 | 70.0 | `bucket(70,'magazine')` |
| 装填时间 | 1.7 秒 | 1.7 秒 | `1.7 ÷ (1+0)` |

**注意**：伤害分布表里的「触发率」列不是这里的静态面板值，而是
`当前触发率 × 该类型占比`，**占比分母是全分布**（触发池含所有伤害类型，§0.3 ②）：
火 `0.31 × 0.6491 = 20.1%`，切割 `0.31 × 0.1474 = 4.6%`。
这个占比与「DoT 加权每层秒伤」用的占比**分母不同**，见 L7 的说明。

## 四、乘区拆解（「每个乘区都能复算」的落点）

`bucketBreakdown()` 返回的四个乘区，每个都能用一条式子复算：

```
BUCKET(面板, stat) = ( panel × (1 + pct) + flat ) × mul
```

| 乘区 | panel | pct | flat | mul | value | 贡献者 |
|---|---|---|---|---|---|---|
| critChance | 0.23 | 1.50 | 0 | 1 | 0.575 | point_strike:pct:150 |
| critMultiplier | 2.10 | 1.20 | 0 | 1 | 4.62 | vital_sense:pct:120 |
| statusChance | 0.31 | 0 | 0 | 1 | 0.31 | — |
| fireRate | 11.6667 | 0 | 0 | 1 | 11.6667 | — |

复算：`0.23 × (1 + 1.50) = 0.575` ✅

## 五、备选 Mod 的增幅（「口径」为什么重要）

增幅 = `装上该 Mod 后的伤害 ÷ 当前伤害 − 1`，**按选定的口径**比较：

| 候选 Mod | 单次射击 | 持续伤害 |
|---|---|---|
| 重型口径 | **+62.26%** | +62.26% |
| 低温弹头 Prime | **+86.84%** | +86.84% |
| 弹药储备 | **+0.00%** | **+9.03%** |

**弹药储备是理解「口径」最好的例子**：它只加弹匣，**完全不改变单发伤害**——
所以「单次射击」口径下看不出任何收益，但在「持续伤害」口径下因为少装填而 +9%。

> demo 默认口径是**单次射击**（`DEFAULT_METRIC = 'perShot'`），可在备选区用单选按钮切换到
> 单弹头 / 单次射击 / 爆发伤害 / 持续伤害 / DoT 加权每层秒伤 / 六秒异常状态总伤。

## 六、表达式速查（全链路）

```
面板
 └─ L1 玄骸     : panel + panel合计 × 玄骸比例            （加到该元素上）
 └─ L2 基伤     : panel × (1 + Σ基伤% + 镀层%)            （AoE 段不吃镀层）
 └─ L3 元素     : 新面板合计 × Σ该元素% → 槽位 → 同类型先合并 → 两两配对
 └─ L4 暴击     : cc = 面板cc×(1+Σcc%)+flat ;  cd = 面板cd×(1+Σcd%)+flat
 └─ L5 命中期望 : Σ档位 概率 × (1 + k×(cd−1)) × 爆头倍率 × (爆头∧暴击 ? 2 : 1)
 └─ L6 输出     : 单发 = 单弹头 × (1+Σ多重%) ; DPS = 单发 × 射速
 └─ L7 DoT      : 基础值 × 系数 × (1+该元素%) × (1+异常伤害%) × (1+派系%)
```
