# 武器分类与 Mod 适用范围设计

> 状态：**待确认**（D-053）。确认后作为"逐件验证 Mod / 赋能"的工作依据。
> 本文档回答一个问题：**某件武器到底能装哪些 Mod？怎么在不手写 442 条映射的前提下判定？**

---

## 1. 现状盘点

数据里已有两套分类信息，都来自紫卡（Riven）体系：

| 字段 | 位置 | 含义 | 取值示例 |
|---|---|---|---|
| `slots.broad` | `weapon-slots.json` | 槽位大类 | `rifle` / `shotgun` / `sniper` / `bow` / `pistol` / `melee` / `archgun` |
| `slots.specific[]` | 同上 | 武器专属类别 | `sword` / `hammer` / `glaive` / `bow` |
| `slots.basis.zkClass` | 同上 | 紫卡分类（**最细**） | `rifle` / `shotgun` / `sniper` / `bow` / `launcher` / `shotgun_sidearm` / `dual_pistols` / `glaive` |
| `modKinds[]` | 同上 | 该武器能装的 Mod 类 | `rifle` / `primary` / `shotgun` / … |

Mod 侧的 `slotKind` 分布（共 442 条）：

```
rifle 112   pistol 104   melee 103   shotgun 83   primary 10
glaive 9    assault_rifle 8   tome 8   sniper 3   bow 1   dual_daggers 1
```

另有 `official.compatName` 标注**武器专属 Mod**（442 条）。

## 2. 问题：光靠 slotKind 不够

同一把"步枪"槽的武器，实际能装的 Mod 差别很大：

```
普通步枪      → 步枪 Mod 全可用
狙击枪        → 步枪 Mod 大部分可用，但狙击专属 Mod（如 尖锐的铅弹）只有狙击能用
弓箭          → 步枪 Mod 可用，但弓箭专属 Mod 只有弓能用
发射器        → 步枪 Mod 可用，但范围/弹道类 Mod 各有归属
霰弹          → 完全独立的 shotgun 槽位，与 rifle 互斥
```

霰弹是最容易区分的（`slotKind: shotgun` 独立），
**难点在 rifle 槽内部**：狙击 / 弓箭 / 发射器都挂在 `rifle` 槽下，
但各自有专属 Mod，不能互相装。

---

## 3. 提议的判定规则（三级）

判定"武器 W 能否装 Mod M"按顺序：

```
① 槽位大类（broad）
   若 M.slotKind 是 shotgun / sniper / bow / glaive 等**独立大类**，
   则 W 的 broad 必须与之匹配，否则不可装。
   → 这一级已经解决了霰弹、投掷类的互斥。

② 武器专属（compatName）
   若 M.official.compatName 存在，则 W 的显示名必须与之对应，
   否则不可装。
   → 这一级已经解决了"某把武器专属 Mod"（442 条）。
   → 现有 isModCompatibleWithWeapon() 已实现这一级。

③ 细分类（zkClass）——**本轮新增**
   对②未覆盖的 Mod，再按 zkClass 精判：
     sniper  → 只有 zkClass === 'sniper' 的武器能用
     bow     → 只有 zkClass === 'bow' / 'crossbow' 的武器能用
     launcher→ 只有 zkClass === 'launcher' 的武器能用
   → 解决"狙击专属 Mod 被普通步枪装上"这类误判。
```

### 3.1 zkClass → 中文名与 Mod 归属

| zkClass | 中文 | 数量 | Mod 槽位归属 |
|---|---|---|---|
| `rifle` | 步枪 | 122 | `rifle` + 通用 `primary` |
| `shotgun` | 霰弹枪 | 39 | `shotgun` |
| `sniper` | 狙击枪 | 15 | `sniper` + `rifle` |
| `bow` | 弓箭 | 17 | `bow` + `rifle` |
| `crossbow` | 弩 | 5 | `bow` + `rifle` |
| `launcher` | 发射器 | 12 | `rifle` + 发射器专属 |

| `dual_pistols` | 双持手枪 | 33 | `pistol` |
| `shotgun_sidearm` | 副手霰弹 | 9 | `shotgun` + `pistol` |

## 4. 验证顺序（分批，每批产出清单）

**原则**：先跑数据筛查找出可疑项 → 人工确认 → 落成测试。

### 第 0 批：分类基线（不动 Mod，先把武器分对）
- 按 zkClass 导出全部主武器的细分类清单
- 检查有没有 `zkClass` 为空但实际应归类的武器
- 产出：`docs/武器分类清单.md`

### 第 1 批：主武器 · 步枪
- 112 条 rifle Mod + 10 条 primary 通用 Mod 逐条确认归属
- 重点：哪些其实是狙击/弓箭/发射器专属（应排除出纯步枪池）

### 第 2 批：主武器 · 霰弹
- 83 条 shotgun Mod
- 重点：副手霰弹（`shotgun_sidearm`，9 把）能否共用

### 第 3 批：主武器 · 狙击 / 弓箭 / 发射器
- 分别确认专属 Mod，以及它们是否共享 rifle 池

### 第 4 批：副手
- 104 条 pistol Mod
- 重点：**投掷类（glaive）**、**爆炸类发射器**的专属 Mod

### 第 5 批：赋能
- 按武器大类分配（rifle / shotgun / pistol / melee 各一套）

**暂不处理**：近战、空战、显赫武器。

## 7. Mod 收录范围：**全部收录**（D-054 提议）

需求方问："是不是应该把所有 mod 都放进来，毕竟可以用来占位，还是只放伤害性？"

**建议：全部收录**，理由：

1. **占位是真实需求** —— 配卡时经常用功能 Mod 填槽，
   如果这些卡不在备选区，就没法如实还原配卡，槽位数量也算不对；
2. **功能 Mod 并非全部零收益** —— 装填速度、弹匣容量已经证实影响持续伤害（D-037），
   归类判错就会漏算伤害；
3. **劣化槽需要它们** —— 劣化槽本来就只接受功能 Mod；
4. **数据量不大** —— 主武器共 224 条，其中纯功能仅 48 条。

按 `slotKind` 统计（主武器 + 副手）：

| slotKind | 总数 | 伤害性 | 纯功能 |
|---|---|---|---|
| `rifle` | 112 | 88 | 24 |
| `shotgun` | 83 | 65 | 18 |
| `pistol` | 104 | 83 | 21 |
| `assault_rifle` | 8 | 3 | 5 |
| `tome` | 8 | 3 | 5 |
| `sniper` | 3 | 2 | 1 |
| `bow` | 1 | 1 | 0 |
| `glaive` | 9 | 2 | 7（近战，本阶段不做） |

**做法**：全部收录，但在备选区**用筛选区分**：
- 默认显示伤害性 Mod；
- 「劣化 / 其他」筛选可以看到纯功能 Mod；
- 每张卡标注它是否进伤害乘区（现已有 `DAMAGE_AFFECTING_STATS` 黑名单）。

这样既能占位，又不会让伤害性 Mod 淹没在功能卡里。
